# Scanner request isolation — bounded repair

The background `ScannerService` mutates one shared orchestrator before awaiting symbol selection and scan workers. Two requests reproduce mode/leverage/exchange replacement during the first scan. Cancelling its coroutine does not stop its thread. The synchronous scanner route uses a lock, but the background service, SMC update routes and debug scan do not share that protection. Bot sessions construct separate orchestrators.

Decision: serialize all mutations/use of the shared scanner engine with the existing application `threading.Lock`, held by the actual worker for its whole operation. Move blocking scanner routes to worker threads so waiting for that lock cannot block the API event loop. A cancelled job discards later progress/results, skips execution if still queued, and retains worker ownership until physical execution returns. Preserve current signal selection, mode thresholds and payloads.

Alternatives: a fresh orchestrator per request allows concurrency, but changes cache/cooldown/risk and service initialization ownership; that requires a wider design. An asyncio lock around `run_in_executor` releases on cancellation before the thread finishes and does not protect synchronous callers. Neither is the bounded fix for this reproduced failure.

Blast radius: UI background-run creation/poll/cancel -> scanner service -> shared orchestrator configuration, ingestion, scan, result transform and logs. Legacy synchronous signal calls, debug schema scans and SMC configuration updates use that same engine and must use the same lock. Paper/live service engines are separate and unchanged. Affected files: `backend/services/scanner_service.py`, `backend/routers/scanner.py`, `backend/api_server.py`, focused regression tests and audit documentation. No new API/schema; queued jobs may wait longer because overlapping use of one mutable engine is serialized.

Verification: controlled offline worker barriers reproduce cross-request mutations; exercise running/queued cancellation, physical worker drain, failure release, log recipient, concurrent synchronous route/config updates and API event-loop responsiveness. Run existing scanner tests plus structural contract/smoke checks. Rollback: revert this bounded diff together; do not remove exclusion from only one caller. No exchange calls or production bot starts are part of verification.

Verification: both original races reproduced. Ten regression cases now pass, including a cancelled active worker followed by twenty queued jobs without filling the shared thread pool. Combined scanner/contract tests: 47 passed, two existing Pydantic deprecation warnings. All four contract inventories and eight smoke categories compare clean. A per-service admission semaphore is released by physical future completion, not cancellation of its caller. This complements the shared engine lock and prevents background waiter starvation of unrelated executor work. Local changes only.
